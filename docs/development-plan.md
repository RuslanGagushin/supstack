# План: дальнейшее развитие Supstack

Составлен 12 ноября 2026 г. для версии 0.31.1, по чтению кода и документации. Приложение и тесты при этом не запускались, поэтому все оценки скорости ниже — предположения, которые первый этап должен проверить замерами.

Цель — описать, куда приложение может расти после того, как модель «блокноты → список → заметка» и чтение по умолчанию доведены (см. `reading-view-plan.md`). Формат хранилища остаётся прежним: обычные `.md` в `cards/`, `daily notes/`, `attachments/`, принадлежность блокнотам — в поле `parents`.

План разбит на пять этапов и сквозной раздел. Этапы 1 и 5.1 не зависят от остальных; этапы 2–4 опираются на замеры из этапа 1. Внутри этапа каждая строка таблицы — отдельный коммит, после каждого `npm test` (и `npm run test:rust`, если тронут плагин).

## Что есть и чего не хватает

| Область | Сейчас | Чего не хватает |
|---|---|---|
| Открытие хранилища | `readVault` читает и разбирает каждую заметку, текст держится в памяти (`web/src/js/services/vault.js:144–194`) | кэша между запусками; замеров на больших хранилищах |
| Изменения извне | раз в 4 с и при возврате в окно перечисляется всё хранилище (`web/src/js/ui/boot.js:33–34`, `vault.js:262–308`) | слежения за файлами вместо полного обхода |
| Поиск | каждое слово ищется подстрокой в тексте каждой заметки (`web/src/js/core/board-model.js:25–31`); фрагмент с совпадением показывается | индекса и ранжирования |
| Связи | обратные ссылки и упоминания без ссылки под заметкой (`web/src/js/ui/editor-toolbar.js:92–93`) | встраивания заметки: `![[заметка]]` рисуется как ссылка (`web/src/js/ui/markdown.js:204`) |
| Задачи | повестка на день и неделю, список по состояниям, запросы (`web/src/js/ui/agenda.js:133–149`) | напоминаний, месяца, быстрого захвата вне окна |
| Синхронизация | git по HTTPS с токеном (`tauri-plugin-vault/src/git.rs:342–354`); конфликт — файл рядом | SSH, истории заметки, разбора конфликтов в приложении; на Android хранилище лежит дважды |
| Платформы | Windows, macOS, Android arm64 (`.github/workflows/apps.yml:24, 63, 102`) | Linux, iOS, нотаризации macOS, магазинов для Android |
| Отмена | 20 последних действий, в памяти (`web/src/js/services/save.js:58–68`) | переживает ли перезапуск — нет |
| Инструменты | 228 тестов страницы, Rust-тесты плагина, проверка слоёв | линтера и проверки типов; `tests/ui.test.mjs` — 1378 строк в одном файле |

## Этап 1. Надёжность и масштаб

Начинать отсюда: без замеров неизвестно, что из остального нужно переделывать.

| Что | Где | Как |
|---|---|---|
| Большое демо-хранилище | новый `scripts/big-vault.mjs`, `tests/harness.mjs` | генератор на 1, 5 и 10 тыс. заметок с вложенными блокнотами, задачами и ссылками; в харнессе — способ открыть его в памяти |
| Замеры | новый `tests/perf.test.mjs` | время `readVault`, одного `pollChanges` без изменений, `computeModel` с запросом, первой отрисовки списка; тест печатает числа и падает только при превышении щедрого порога |
| Слежение за файлами (компьютер) | `tauri-plugin-vault/src/desktop.rs`, `src/commands.rs`, `web/src/js/services/fs.js`, `boot.js:33` | крейт `notify`: плагин шлёт событие с изменёнными путями, страница перечитывает только их; интервал 4 с остаётся запасным и редеет до минуты |
| Дешёвый обход (Android) | `tauri-plugin-vault/android/…/VaultPlugin.kt:273–297`, `vault.js:262–308` | `list` уже может отдавать время изменения; `pollChanges` не должен вызывать `getFile()` для заметки, чьё время не изменилось |
| Кэш индекса | `vault.js:23–29, 144–194`, новый `web/src/js/services/index-cache.js` | хранить по пути `mtime`, размер, frontmatter, теги, ссылки; при открытии разбирать только изменившиеся файлы. Кэш — на устройстве, не в хранилище |
| Линтер и типы | `package.json`, `.github/workflows/tests.yml` | ESLint с минимальным набором правил; `tsc --checkJs --noEmit` сначала только для `web/src/js/core/` |
| Разбить `ui.test.mjs` | `tests/ui.test.mjs` | по экранам: список, редактор, повестка, настройки; общие шаги — в `tests/harness.mjs` |

Текст заметок по требованию (не держать `raw` всех заметок в памяти) в этот этап не входит: решение принимается по замерам. Если 10 тыс. заметок открываются за приемлемое время с кэшем индекса, оно не нужно.

Готово, когда `npm test` печатает четыре замера для хранилища на 10 тыс. заметок, а правка одного файла во внешнем редакторе на компьютере не вызывает обхода всего хранилища.

## Этап 2. Поиск и связи

| Что | Где | Как |
|---|---|---|
| Индекс для поиска | новый `web/src/js/core/search.js`, `board-model.js:25–31` | обратный индекс слов, обновляемый по событию `changed`; порядок результатов: совпадение в названии, затем в заголовках, затем в тексте; `+tag` / `-tag` работают как сейчас |
| Фрагмент с совпадением | `web/src/js/ui/cards.js:126–133` | уже есть: строка вокруг первого совпадения с подсветкой. Остаётся убрать из него сырой Markdown (см. `visual-polish-plan.md`, этап 1) |
| Встраивание заметки | `markdown.js:196–205`, `web/src/js/ui/live-preview.js:129` | `![[заметка]]` и `![[заметка#заголовок]]` показывают текст; глубина вложения ограничена, цикл показывается ссылкой |
| Формулы и диаграммы | `markdown.js`, `scripts/vendor.mjs`, `src-tauri/tauri.conf.json` (CSP) | только по запросу пользователей: KaTeX и Mermaid заметно увеличат страницу; грузить лениво, при первой формуле или диаграмме |

Готово, когда запрос из двух слов по хранилищу на 10 тыс. заметок отвечает без заметной задержки (порог — из замеров этапа 1), а заметка с названием из запроса стоит выше заметки, где слово только в тексте.

## Этап 3. Задачи и захват

| Что | Где | Как |
|---|---|---|
| Напоминания | `src-tauri/Cargo.toml`, `capabilities/`, новый `web/src/js/services/reminders.js`, `web/src/js/core/org.js` | `tauri-plugin-notification`: уведомление для `SCHEDULED` и `DEADLINE` со временем. На компьютере — пока приложение запущено; на Android — запланированные заранее, пересчёт после каждого сохранения |
| Месяц в повестке | `agenda.js:25, 133–137`, `web/src/css/agenda.css` | третье значение `AG.span`: сетка месяца с числом задач в дне, нажатие открывает день |
| Быстрый захват с клавиатуры | `src-tauri/src/lib.rs`, `capabilities/desktop.json` | `tauri-plugin-global-shortcut`: сочетание открывает маленькое окно с формой захвата повестки |
| «Поделиться в Supstack» | `tauri-plugin-vault/android/src/main/AndroidManifest.xml`, `VaultPlugin.kt` | приём `ACTION_SEND` с текстом или ссылкой: новая заметка в выбранном блокноте или строка в заметке дня |
| Экспорт в календарь | новый `web/src/js/core/ics.js` | файл `.ics` из задач с датами; только экспорт, без обратной синхронизации |

Набор состояний задач остаётся фиксированным: шесть значков уже нарисованы в трёх местах, и настраиваемые состояния ломают совместимость с другими редакторами.

Готово, когда задача с `SCHEDULED: <… 10:00>` даёт уведомление в 10:00 на Android при закрытом приложении.

| Вход без ручного токена | `web/src/js/ui/shell.js` (настройки Git), `git.rs:342–354` | для GitHub — device flow: код на экране, подтверждение в браузере; токен кладётся туда же, куда сейчас |
| SSH | `tauri-plugin-vault/Cargo.toml` (`git2` без `ssh`), `git.rs:342–354` | включить `ssh` в `git2`, ключ — из файла, пароль ключа — в системном хранилище. Только компьютер: на Android это тянет сборку libssh2 |
| Одна копия на Android | `git.rs:612–840` (зеркало), `VaultPlugin.kt` | варианты: хранилище в приватной папке приложения (теряется доступ из других программ) или разрешение «ко всем файлам» (не пройдёт в Google Play). Оба меняют обещание из README; сначала решить, нужно ли |

Готово, когда заметку можно вернуть к версии недельной давности, не выходя из приложения, а конфликтная копия исчезает после выбора в диалоге.

| Что | Где | Как |
|---|---|---|
| Linux | `.github/workflows/apps.yml`, `scripts/updater-manifest.mjs`, `README.md` | задание на `ubuntu-24.04`: AppImage и `.deb`. `keyring` уже собран с `linux-native` (`tauri-plugin-vault/Cargo.toml`); проверить хранение токена и обновление AppImage |

## Порядок

1. Этап 1 целиком и Linux из этапа 5 — параллельно, они не пересекаются по файлам.
2. Этап 2: поиск и фрагменты; встраивание заметок.
3. Этап 3: напоминания первыми — это самая заметная нехватка для приложения с повесткой.
4. Этап 4: история и разбор конфликтов; вход через GitHub.
5. Остальное из этапа 5 — по мере появления пользователей на этих платформах.

## Что не входит

- Изменение формата хранилища и поля `parents`.
- Собственный сервер синхронизации: git и сторонние средства (Syncthing) остаются единственными способами.
- Плагины и пользовательские скрипты: строгий CSP (`tests/csp.test.mjs`) — часть модели безопасности.
- Совместное редактирование в реальном времени.
