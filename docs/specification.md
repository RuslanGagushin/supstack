# Supstack: спецификация развития

Версия документа 3 · 12 ноября 2026 г. · исходная версия приложения 0.31.1

Отметка «Статус» в таблицах показывает, что уже сделано: ✅ — выполнено и проверено, пусто — ещё нет.

Составлена по двум планам: `docs/development-plan.md` (функции и платформы) и `docs/visual-polish-plan.md` (интерфейс). Планы отвечают на вопрос «что и где менять в коде»; эта спецификация фиксирует, **что должно получиться и как это проверить**. Ссылки на файлы и строки остаются в планах.

## 1. Рамки

Спецификация описывает изменения поверх 0.31.1 в четырёх областях: масштаб и надёжность, поиск и связи, задачи, интерфейс. Новые функции синхронизации и новые платформы в эту версию не входят (раздел 9).

Слова «должно» и «не должно» обозначают обязательные требования. «Может» — допустимое, но не обязательное поведение. Требование считается выполненным, когда проходит проверка из его строки.

Числа в разделе 5 получены замером живой страницы на демо-хранилище. Числовых порогов скорости в разделе 4.1 пока нет: приложение на большом хранилище не замерялось, пороги задаёт требование PERF-2.

## 2. Термины

| Термин | Значение |
|---|---|
| Хранилище | папка с заметками, которую открыл пользователь |
| Заметка | файл `.md` в `cards/` или `daily notes/` |
| Блокнот | заметка, на которую другая заметка ссылается в поле `parents` |
| Список | средняя колонка: блокноты и заметки текущего блокнота |
| Чтение / правка | два режима открытой заметки |
| Повестка | экран задач по дням (`Agenda`) |
| Чип | короткая плашка с датой или состоянием задачи |
| Среднее окно | окно шириной от 821 до 1180 px |
| Телефон | окно не шире 820 px или устройство с `pointer: coarse` |

## 3. Инварианты

Эти свойства не должно нарушать ни одно изменение.

| № | Инвариант |
|---|---|
| INV-1 | Заметки остаются обычными файлами Markdown. Приложение добавляет только нужный ему frontmatter. |
| INV-2 | Структура хранилища не меняется: `cards/`, `daily notes/`, `attachments/`, настройки в `.supstack/settings.json`, принадлежность блокнотам в `parents`. |
| INV-3 | Хранилище, открытое в Supstack, продолжает работать в Obsidian, любом редакторе, Git и Syncthing. |
| INV-4 | Кэши и индексы хранятся на устройстве, а не в хранилище. |
| INV-5 | Набор состояний задач фиксирован: `[ ]`, `[/]`, `[<]`, `[x]`, `[-]`, `[>]`. |
| INV-6 | Слои `core → services → ui` сохраняются; `tests/architecture.test.mjs` проходит. |
| INV-7 | Политика CSP не ослабляется; `tests/csp.test.mjs` проходит. |
| INV-8 | Токен доступа к git не попадает в хранилище и в хранилище страницы. |
| INV-9 | Каждая новая строка интерфейса есть на английском и русском. |
| INV-10 | При конфликте синхронизации текст ни одной из сторон не теряется. |

## 4. Функциональные требования

### 4.1. Масштаб и надёжность

| № | Требование | Проверка | Статус |
|---|---|---|---|
| PERF-1 | Должен быть генератор демо-хранилища на 1, 5 и 10 тыс. заметок с вложенными блокнотами, задачами и ссылками. | `scripts/big-vault.mjs` создаёт хранилище, которое открывается в тестовом харнессе. | ✅ |
| PERF-2 | Тесты должны измерять и печатать четыре величины на 10 тыс. заметок: открытие хранилища, один опрос изменений без изменений, поиск по запросу из двух слов, первую отрисовку списка. Первый замер (страница в Chromium, плагин отвечает из памяти, без диска): открытие 640–710 мс, опрос 12 мс, поиск 175 мс, список 275–355 мс. Пороги — примерно в пять раз выше: 5000, 300, 1500 и 1500 мс. | `npm test` печатает четыре числа (`tests/perf.test.mjs`); тест падает при превышении порога. | ✅ |
| PERF-3 | На компьютере изменение файла вне приложения должно подхватываться по событию файловой системы, без обхода всего хранилища. Полный обход остаётся запасным и выполняется не чаще раза в минуту. | Правка одного файла внешним редактором приводит к чтению одного файла; заметка обновляется в окне не позже чем через 2 с. |  |
| PERF-4 | На Android опрос изменений не должен читать заметку, время изменения которой не изменилось. | Опрос без изменений не вызывает чтения ни одного файла. |  |
| PERF-5 | Повторное открытие хранилища должно разбирать только файлы, изменившиеся с прошлого открытия. | После перезапуска без изменений число разобранных заметок равно нулю. |  |
| PERF-6 | Повреждённый или устаревший кэш не должен мешать открытию: он отбрасывается и строится заново. | Тест с испорченным файлом кэша открывает хранилище полностью. |  |
| QA-1 | В CI должны выполняться линтер и проверка типов для `web/src/js/core/`. | Задание в `tests.yml` падает на ошибке линтера или типов. |  |
| QA-2 | Тесты интерфейса должны быть разбиты по экранам: список, заметка, повестка, настройки. | Ни один файл в `tests/` не длиннее 500 строк. |  |

### 4.2. Поиск и связи

| № | Требование | Проверка |
|---|---|---|
| SRCH-1 | Поиск должен работать по индексу слов, который обновляется при изменении заметок. | Время поиска из PERF-2 укладывается в порог. |
| SRCH-2 | Результаты должны идти в порядке: совпадение в названии, затем в заголовках, затем в тексте. | Заметка с названием из запроса стоит выше заметки, где слово только в тексте. |
| SRCH-3 | Фильтры `+tag` и `-tag` и области «Here / Everywhere» должны работать как сейчас. | Существующие тесты поиска проходят без изменений. |
| SRCH-4 | Фрагмент с совпадением не должен содержать служебной разметки задач: `[#A]`, `[>]`, `[-]`, `[/]`, `[<]`. | Тест на заметке с задачами. |
| LINK-1 | `![[заметка]]` и `![[заметка#заголовок]]` должны показывать текст заметки или её раздела в чтении и в правке. | Тест рендера. |
| LINK-2 | Вложение встраиваний ограничено тремя уровнями; цикл и превышение глубины показываются ссылкой. | Тест на двух заметках, встраивающих друг друга. |
| LINK-3 | Формулы и диаграммы может быть добавлены позже; если добавляются, их библиотеки должны загружаться только при первой формуле или диаграмме. | Размер страницы без формул не растёт. |

### 4.3. Задачи и захват

| № | Требование | Проверка |
|---|---|---|
| TASK-1 | Задача с `SCHEDULED` или `DEADLINE` и временем должна давать системное уведомление в это время. | На Android уведомление приходит при закрытом приложении; на компьютере — при запущенном. |
| TASK-2 | Уведомления должны пересчитываться после каждого сохранения и после синхронизации. Закрытая или удалённая задача уведомления не даёт. | Тест: задача закрыта до срока — уведомления нет. |
| TASK-3 | Разрешение на уведомления запрашивается при первой задаче со временем, а не при запуске. Отказ не мешает работе. | Ручная проверка на Android и macOS. |
| TASK-4 | Повестка должна иметь вид «месяц»: сетка дней с числом задач, нажатие открывает день. | Тест рендера; переключатель «Day / Week / Month». |
| TASK-5 | На компьютере глобальное сочетание клавиш должно открывать окно быстрого захвата. Сочетание настраивается и может быть отключено. | Ручная проверка на Windows и macOS. |
| TASK-6 | На Android приложение должно принимать текст и ссылки через «Поделиться» и создавать заметку в выбранном блокноте или строку в заметке дня. | Ручная проверка. |
| TASK-7 | Задачи с датами должны выгружаться в файл `.ics`. Обратного импорта нет. | Файл открывается в системном календаре. |

## 5. Требования к интерфейсу

### 5.1. Раскладка

| № | Требование | Проверка |
|---|---|---|
| UI-1 | При открытой заметке колонка её текста не должна быть уже 400 px, а сама панель заметки — уже 480 px. Сейчас при окне 860 px панель 200 px, текст 119 px. | Замер на ширинах 1280, 1100, 1024, 900 и 830 px. |
| UI-2 | В окне уже 1180 px с открытой заметкой боковая панель должна сворачиваться сама. Если пользователь раскрыл её вручную, выбор сохраняется до изменения ширины окна. | Тест на 1100 px. |
| UI-3 | В окне уже 960 px заметка должна открываться поверх списка, с «‹ блокнот» в шапке. | Тест на 900 px. |
| UI-4 | Предпросмотр файла на экране «Files» не должен показываться колонкой уже 320 px; тогда файл открывается на месте списка. | Тест с открытой заметкой на 1440 px. |

### 5.2. Заметка

| № | Требование | Проверка |
|---|---|---|
| UI-5 | В чтении чипы дат и примечание задачи должны начинаться на одной вертикали с текстом задачи. Сейчас они на 73 px левее. | Тест сравнивает левые края. |
| UI-6 | В правке ключ и его дата (`scheduled` + дата) не должны разрываться переносом строки. | Тест на ширине 412 px. |
| UI-7 | Правый отступ панели форматирования должен быть 12 px, как у шапки заметки. | Замер. |
| UI-8 | Блок «Linked mentions» должен идти после текста с отступом 32 px, без разделительной линии. | Снимок экрана. |

### 5.3. Телефон

| № | Требование | Проверка |
|---|---|---|
| UI-9 | У каждой кнопки меньшая сторона области нажатия должна быть не меньше 40 px; у значка состояния задачи — 32 px. Сейчас: 30×30, 29×28, высота 26 и 14–15 px. | Расчёт по странице для списка, заметки в правке и повестки. |
| UI-10 | Панель форматирования должна прокручиваться по горизонтали с затуханием у правого края. | Снимок экрана. |
| UI-11 | Подсказки клавиш (строка под повесткой, низ палитры команд, сочетания в её строках) не должны показываться на устройствах без наведения. | Тест с `hover: none`. |
| UI-12 | Фильтры состояний в списке задач должны стоять в одну строку и прокручиваться; подписи не переносятся. | Тест на 412 px. |

### 5.4. Повестка

| № | Требование | Проверка |
|---|---|---|
| UI-13 | Задача с планом и сроком показывается в день плана и в день срока. Строка «In N d.» есть только в сегодняшнем дне. Задача из «Overdue» не повторяется в прошедших днях. | В демо-хранилище «Book the Pont du Gard tour» встречается в неделе не больше двух раз (сейчас четыре). |
| UI-14 | Сетка часов показывается только между первым и последним событием дня со временем, с шагом в час. Линия «сейчас» остаётся. | В дне без событий со временем нет линий сетки. |
| UI-15 | День без записей — одна приглушённая строка, без рамки карточки. | Снимок экрана. |
| UI-16 | Заголовок недели — диапазон дат («9–15 November») и приглушённый номер недели. «Log» — переключатель в ряду управления. | Тест текста заголовка на обоих языках. |
| UI-17 | Подписи чипов не содержат сокращений вида «Sched.2x». | Тест строк. |
| UI-18 | В списке задач название заметки — приглушённая подпись после названия задачи, а не отдельная колонка. | Снимок экрана на компьютере и телефоне. |
| UI-19 | В форме захвата кнопки называются «Save» и «Cancel»; буквы шаблонов показаны как клавиши, отдельно от названия. | Тест строк. |

|---|---|---|
| A | UI-5 – UI-8, UI-11, SRCH-4, UI-28 (явные дефекты) | — |
| B | UI-1 – UI-4 (среднее окно), UI-9, UI-10, UI-12 (телефон) | — |
| C | PERF-1 – PERF-6, QA-1, QA-2 | — |

## 9. Вне рамок

- Изменение формата хранилища и поля `parents`.
- Собственный сервер синхронизации.
- Плагины и пользовательские скрипты.
- Совместное редактирование в реальном времени.
- Шифрование хранилища.
- Настраиваемые состояния задач.
- Новые платформы и распространение: Linux, iOS, нотаризация macOS, F-Droid и Google Play. Сборки выходят для Windows, macOS и Android, как в 0.31.1.
- Новые функции синхронизации: история заметки, разбор конфликтов в приложении, вход через GitHub, SSH, одна копия хранилища на Android. Отложены; существующая синхронизация работает как в 0.31.1.
- Сохранение стека отмены между запусками.

## 10. Что не проверено

- Скорость на больших хранилищах не измерялась; раздел 4.1 исходит из чтения кода.
- Нативные приложения не запускались: требования раздела 5 проверены на странице в браузере.
- Контраст чипов дат не рассчитан надёжно (A11Y-3).
- Режим выбора нескольких заметок не разбирался и требований к нему здесь нет.
